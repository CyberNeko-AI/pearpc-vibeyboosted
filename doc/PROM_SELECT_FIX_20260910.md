# SDL 下 PROM select 启动菜单无响应

`prom_bootmethod = "select"` 在 `prom_user_boot_partition()` 中等待 CUDA
按键，但 SDL 的 `runUI()` 在 `prom_load_boot_file()` 返回之后才启动。
主线程因而一直等按键，无法处理产生按键的 SDL 事件，也无法正常刷新菜单。
已有 select 捕获的调用栈停在该等待循环，客户机 CPU 尚未启动。

修复为 `SystemDisplay` 增加启动菜单事件轮询接口。SDL 在主线程轮询事件并
刷新显示；有独立事件线程的其他后端保持默认行为。菜单等待按键时调用该接口，
收到窗口关闭事件则退出等待。正常运行的 SDL 事件循环保持原样。

同时用 CUDA 已有互斥锁保护 PROM 对键盘包的读取和清除；消费包后唤醒事件
工作线程，避免并发覆盖新按键及不必要的超时等待。

验证：`make -j4` 成功。用户手动确认本轮修改恢复 select 启动。
测试进程使用硬盘和 NVRAM 副本；原配置、磁盘镜像和崩溃转储未加入提交。

后续回归可用 select 分别选择硬盘和光盘，检查数字键、回车、0 切换列表、
ESC 退出及窗口关闭；auto 模式应仍能直接启动。
